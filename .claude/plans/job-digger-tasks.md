# Job Digger - перелік задач за етапами

Повний обсяг робіт за технічним планом v1.4.0 ([карта документації](../../docs/README.md)).

> **Джерело правди - дошка Trello «JD - Job Digger»**: https://trello.com/b/8UsxKeak/jd-job-digger
>
> Цей файл - статичний довідник обсягу робіт. Він фіксує список задач один раз, галочки в ньому під час роботи не проставляються. Актуальний стан задачі (Backlog / To Do / In Progress / Testing / Done) дивись у Trello.

Одна задача = одна картка Trello = одна гілка Git. Маленькі кроки задачі - чекліст усередині картки, один крок = один commit ([розділ 14](../../docs/process.md)).

Нумерація `N.MM` відповідає назвам карток: N - етап, MM - задача в етапі. Задачі, додані після первинного розбиття, дописуються в кінець свого етапу, щоб номери наявних карток не зсувалися. Порядок роботи задає колонка To Do, а не номер; де це важливо, в описі картки стоїть «брати перед X.YY».

## Задачі поза початковим планом

Додані під час розбиття на картки, бо закривають реальні прогалини:

- **1.02** `.nvmrc` і `engines` - локально й на Vercel має бути одна версія Node.
- **1.02** Коренева `README.md` - README лежить лише в `docs/`, тож сторінка репозиторію на GitHub порожня.
- **1.03 + 1.12** ESLint і Prettier - у плані описані тести в CI, але про стиль коду не сказано нічого.
- **1.07** `.env.example` - ENV згадуються в шести файлах плану, єдиного переліку немає.
- **1.12** Кеш браузерів Playwright у Actions - інакше кожен PR качає Chromium заново.
- **2.07** Seed-скрипт - для ручної перевірки картки в колонці Testing потрібні дані.

Додані 15.11.2026 після прогону плану через Grill Me (задача 1.13) і розбору колонки Analyze:

- **1.14** Хук форматування падав на файлах поза репозиторієм і хибно блокував крок.
- **1.15** Попередження npm про install-scripts (esbuild, fsevents) потребує рішення, зафіксованого в git.
- **2.09** Механізм показу помилок - план описував лише happy path.
- **2.10** Сортування й пагінація списків - були описані тільки для History, хоч масштаб 300+ компаній.
- **3.21** Стани завантаження й оптимістичні дії - у плані не було нічого.
- **4.12** Polling-маршрут - план вимагав індикатор прогресу, але не механізм, яким клієнт дізнається про серверні зміни.
- **7.09** Пін сторонніх actions за SHA разом із Dependabot - вирішується тоді, коли в CI з'являться секрети Neon і Vercel.

Додана 15.11.2026 під час 2.03, коли інтерфейс переводився на токени HeroUI:

- **2.11** Перемикач теми - у плані було тільки світле оформлення, а темні токени HeroUI лежать під `.dark`/`[data-theme="dark"]` і без `prefers-color-scheme`, тож режим System сам собою не працює.

Решта знахідок рев'ю задач не додала: правила порожніх станів, фіналізації завислого запуску, пріоритетів і скасування в черзі, «Last ok», одноразового підсумку й стійкості CSV записані в плані, а в роботу входять через уже наявні картки - 2.01, 2.03, 2.06, 3.15, 4.01-4.03, 4.06-4.10 і 6.06.
