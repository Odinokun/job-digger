# Job Digger - Огляд: мета, стек, архітектура

Частина технічного плану Job Digger v1.4.0. Карта всіх файлів - у [README](README.md).

## 1. Мета застосунку

**Job Digger** - персональний застосунок для пошуку кар'єрних сторінок компаній, регулярного моніторингу вакансій і відображення нових вакансій.

Основний сценарій:

1. Користувач додає головну адресу компанії або URL її кар'єрної сторінки.
2. Застосунок шукає всі доступні кар'єрні сторінки компанії, включно із зовнішніми платформами.
3. Зберігає компанію та знайдені джерела.
4. Перевіряє вакансії вручну або автоматично.
5. Показує нові вакансії у вкладці **Unread**.
6. Користувач позначає вакансії як Read або Favorite.

Масштаб: від десятків до 300+ компаній із можливістю подальшого зростання.

Користувачі:

- **Етап розробки:** застосунок працює локально, користувач лише автор, авторизації немає.
- **Після розміщення на Vercel:** вхід обов'язковий, спочатку лише для автора.
- **За потреби згодом:** доступ для кількох знайомих. Публічної реєстрації немає.

## 2. Технологічний стек

Стек із версіями - у [`CLAUDE.md`](../CLAUDE.md#стек). Тут - лише те, що стосується онлайн-версії (етап 7): онлайн-БД - PostgreSQL на Neon (безкоштовний тариф), хостинг - Vercel, авторизація - вхід через Google для email зі списку в ENV ([розділ 9](data.md)). Playwright для динамічних сайтів - не в першій версії, пізніше лише за потреби ([розділ 6](discovery-and-parsing.md)).

**База даних:** локально й онлайн використовується той самий PostgreSQL з однаковою основною версією. Тому схема Drizzle одна і набір міграцій один. Адреса бази задається змінною `DATABASE_URL`: локально - база в Docker, на Vercel - Neon. Локальні дані переносяться онлайн через `pg_dump` / `pg_restore` разом зі статусами Read/Favorite.

Усе в стеку можна використовувати безкоштовно: Docker Desktop - для особистого використання, Neon - у межах безкоштовного тарифу (1 ГБ і 100 CU-годин на місяць на проєкт), Vercel - на тарифі Hobby.

## 3. Архітектура системи

Принцип «одне кар'єрне джерело = одне завдання», черга в PostgreSQL і спільний ліміт одночасних джерел - у [`CLAUDE.md`](../CLAUDE.md#архітектура).

Захоплення завдань, повернення завислих і локальний фоновий цикл усередині сервера Next.js уже в коді - [README черги](../src/server/queue/README.md). На Vercel це та сама функція обробки. Її запускає щогодинний обробник розкладу або кнопка Check all. Функція працює до 4,5 хвилини (ліміт - 5 хвилин), і якщо завдання лишилися - запускає себе знову, доки черга не спорожніє.

Сторонні сервіси для черги не потрібні, код обробника однаковий локально й онлайн.

Якщо деякі сайти потребуватимуть важкого Playwright або перевищуватимуть ліміти функцій, для них може знадобитися окремий виконавець. Це технічний резерв, а не обов'язкова частина першої версії.
