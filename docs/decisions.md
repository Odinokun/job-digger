# Job Digger - журнал змін

Номери розділів у записах відповідають нумерації розділів у файлах плану - карта в [README](README.md).

## v1.4.0

Прогін плану через Grill Me (задача 1.13). Рішення v1.3.0 не переглядалися - шукали непокрите: стани помилок в інтерфейсі, порожні екрани, крайні випадки в даних. Робота за кожним пунктом винесена в окремі картки колонки Analyze.

1. **Порожні екрани** (розділи 4, 4.1-4.4): кожен список має текст для порожнього стану, і цей текст розрізняє «даних немає взагалі» (з переходом в Add company) та «у цьому зрізі порожньо» («усе прочитано» для Unread). Порожнього екрана без тексту немає ніде. Check all вимкнена при нулі компаній у Tracked; порожня вкладка Not tracked - бажаний стан.
2. **Помилки й очікування в інтерфейсі** (розділ 4): дія, яка не вдалася, повідомляє про себе коротким сповіщенням, а не завершується тихо; недоступна база дає екран із кнопкою «Спробувати ще раз» замість падіння; поки список завантажується, показуються заготовки рядків; Read і Favorite застосовуються одразу й відкочуються при помилці.
3. **Довгі списки** (розділи 4.1, 4.2): Jobs - від найновішої дати виявлення, Companies - за назвою; по 50 рядків із Load more, наступна порція відраховується від останнього показаного рядка, а не за номером сторінки. Вибору сортування немає.
4. **Формат дат і лічильник unread** (розділи 4.1, 4.2, 4.4): дата виявлення й час запуску - абсолютні за локаллю, відносний формат лишається для «Last checked» і «Last ok». Лічильник дорівнює вкладці Unread: непрочитана вакансія з позначкою Closed у нього не входить.
5. **Mark all as read** (розділи 4.1, 7): межа - дата виявлення на момент підтвердження, а не перелік завантажених у списку рядків.
6. **Видалення одного джерела** (розділ 4.2): прибирає і його вакансії, зокрема з Favorites - те саме правило, що для Delete компанії. Числа показані біля джерела в модалці Edit, зміна застосовується після Save, окремого діалогу підтвердження немає.
7. **Хронічні збої джерела** (розділи 4.2, 6, 9): джерело веде лічильник послідовних збоїв і час останньої успішної перевірки, у рядку компанії показується «Last ok: 12 days ago». Автоматично з відстеження не знімається.
8. **Довіра до розпарсених даних** (розділи 6, 7): вакансія без title або без http(s)-URL не зберігається і рахується як parse warning; location необов'язкова («—» у списку); відповідь, обрізана лімітом розміру, - збій джерела, а не частковий результат, тож не видаляється нічого.
9. **Фіналізація завислого запуску** (розділи 4.4, 8): запуск закривається, коли не лишилося незавершених завдань, або після 15 хвилин без руху - з тими числами, які є. History лишається з п'ятьма полями, нового статусу немає.
10. **Пріоритети й скасування в черзі** (розділи 4.3, 5, 8): два рівні пріоритету - ручні завдання (Find pages, Check now, Retry) перед фоновими, ліміт 5 спільний. Видалення компанії чи джерела скасовує незавершені завдання, захоплене добігає, а його результат відкидається; закриття модалки Add company скасовує Find pages.
11. **Прогрес і підсумок** (розділи 8, 9): інтерфейс опитує сервер, поки запуск активний, плюс одне опитування на завантаженні сторінки; поза перевіркою опитування немає, при втраті зв'язку - повідомлення і зупинка. Підсумок показується один раз, зокрема при поверненні після закритої вкладки, тож запуск несе позначку показаного підсумку. SSE відкладено: на Vercel Hobby відкрита функція їсть той самий бюджет, що й перевірки.
12. **Failed Sources Drawer** (розділ 8): після Retry останнього невдалого джерела drawer лишається відкритим і повідомляє, що невдалих більше немає.
13. **Стійкість CSV-імпорту** (розділ 10): UTF-8 з BOM і без, розділювач `,` або `;` за рядком заголовка, рівно три очікувані колонки - інакше файл відхиляється цілком, без часткового імпорту; ліміт 5 МБ, дублікати всередині файлу - у числі пропущених.

## v1.3.0

1. **Назва** (заголовок, розділ 1): Job Monitor → Job Digger.
2. **Користувачі та авторизація** (розділи 1, 2, 9, 11): локально - один користувач без авторизації; онлайн - вхід лише через Google для email зі списку в ENV, за потреби доступ для кількох знайомих без публічної реєстрації. Дані користувачів ізольовані. Авторизація - окреме завдання перед розміщенням на Vercel.
3. **Автоматичні перевірки** (розділи 4.5, 8, 12): інтервал зі списку 3, 6, 12 або 24 години, за замовчуванням 6. Відлік від запуску останньої загальної перевірки, ручний Check all перезапускає відлік. Локально - перевірка на старті, якщо остання була понад 1 годину тому, і вимикач `AUTO_CHECK=off`. На Vercel - Vercel Schedules раз на 1 годину, запасний варіант - зовнішній cron.
4. **База даних** (розділи 2, 8, 11): PostgreSQL усюди - локально в Docker, онлайн на Neon (безкоштовний тариф). Одна схема Drizzle, одні міграції, адреса через `DATABASE_URL`, перенесення даних через `pg_dump` / `pg_restore`. SQLite прибрано.
5. **Черга** (розділи 3, 4.5, 6, 8, 9, 11, 12): одне завдання = одне кар'єрне джерело. Черга в PostgreSQL з безпечним захопленням завдань і поверненням завислих. Локально - фоновий цикл у сервері Next.js, на Vercel - функція до 4,5 хв, яка перезапускає себе, доки черга не спорожніє. Паралельність і ліміти сторінок - спільні, через ENV; у Settings - лише інтервал, мова, CSV. Одна загальна перевірка одночасно - для кожного користувача.
6. **Безпека** (новий розділ 13): сервер локально лише на 127.0.0.1, зміни даних через Server Actions, захист від SSRF, вміст сайтів лише як текст, CSV-експорт без формул, онлайн - усе за входом, секрети в ENV, перевірка email на кожному запиті.
7. **Пошук і читання джерел** (розділи 2, 3, 4, 4.3, 5, 6, 10, 11): порядок пошуку - посилання з сайту на ATS, кар'єрні сторінки сайту, ATS за назвою (з позначкою «перевір»). Пробне читання кожної знахідки до вибору. У першій версії читаються лише ATS з API та сторінки з schema.org JobPosting, Playwright відкладено. Список No career page перейменовано на Not tracked зі статусами Not checked, Not found, Unsupported, Check failed.
8. **Без зовнішнього пошукового API** (розділи 5, 12): у першій версії лише три безкоштовні способи пошуку плюс ручне введення кар'єрної адреси.
9. **Пагінація, видалення і ввічливість** (розділи 4.1, 6, 7, 12): один параметр Pages to check = 5, досягнення ліміту - успішна перевірка, Maximum pages limit прибрано (у 6.16 замінено лімітом у вакансіях і глибиною читання - [`src/server/parsers/README.md`](../src/server/parsers/README.md#ліміт-вакансій-і-глибина)). Вакансія, якої немає в успішній перевірці, видаляється з БД. Вакансія з Favorites лишається з позначкою Closed, доки її не приберуть із Favorites. Після помилки перевірки нічого не видаляється. Нуль з API - достовірно, нуль зі сторінки - збій. Ввічливість: до 2 запитів одночасно на сайт, пауза 2 с, тайм-аут 20 с, чесний User-Agent, повага до 429, повтори лише при збоях.
10. **Без фільтра за ключовими словами** (розділ 4.1): зберігаються всі вакансії джерела, основний сценарій - невеликі компанії.
11. **Перша перевірка і Mark all as read** (розділи 4.1, 7): вакансії з першої перевірки нової компанії потрапляють в Unread. У вкладці Unread - кнопка Mark all as read з діалогом підтвердження.
12. **Mark as unread** (розділи 4.1, 4.2): для вакансії - перемикач Mark as Read / Mark as unread. Для компанії на сторінці Sources - Mark all as read і Mark all as unread без діалогу підтвердження.
13. **Без vacancy_history** (розділи 7, 9): таблицю прибрано. Вакансія, що повернулася, просто створюється заново як Unread. У таблиці vacancies додано позначку Closed.
14. **Ключ і поля вакансії** (розділи 4.1, 7, 9): ключ - джерело + ID на платформі, а без ID - очищена URL. Зміна назви лише оновлює назву. Description, salary, employment type не зберігаються. Компанія і source URL - через зв'язки. У списку - назва, компанія, локація, дата виявлення.
15. **Неблокувальний Check all і одночасні зміни** (розділи 7, 8): ручна перевірка не блокує інтерфейс - індикатор у шапці, вакансії з'являються одразу, підсумок наприкінці, перевірка триває після закриття вкладки. Правила одночасних змін: кожна сторона змінює лише свої поля, умовне видалення з урахуванням Favorites, Mark all as read - лише для вакансій на момент підтвердження.
16. **Перетин запусків** (розділи 4.4, 8): нова загальна перевірка не стартує, поки триває інша, а автоматична пропускається. Check now неактивна під час загальної перевірки. Retry - після завершення, рядок History не змінює. Check now і Retry в History не записуються.
17. **Лічильник Unread без сповіщень** (розділ 4.1): кількість непрочитаних - у меню біля Jobs і в назві вкладки браузера. Telegram, email і сповіщень браузера немає.
18. **Сторінка Companies і Delete** (розділи 4, 4.2, 4.3, 5, 8, 10, 11): Sources і Not tracked об'єднано в одну сторінку Companies з вкладками Tracked і Not tracked. Меню: Jobs, Companies, History, Settings. Delete видаляє компанію повністю з попередженням у діалозі. Окреме джерело прибирається через Edit, а після видалення останнього компанія переходить у Not tracked (Not checked).
19. **Find pages і Find new pages** (розділ 4.3): Find pages - пошук для однієї компанії з вибором у модальному вікні. Find new pages (замість Check all на Not tracked) - фоновий повторний пошук для всіх, автоматично додаються лише надійні знахідки, знахідки «за назвою» чекають підтвердження, якщо дошка не веде на сайт компанії (уточнено 19.11.2026, задача 5.05).
20. **Модальне вікно додавання і дублікати** (розділи 5, 9): одна назва модалки - Add company, кнопка пошуку - Find pages. Отримуємо лише назву і домен, «метадані» прибрано. Головна адреса компанії зберігається зі шляхом (bosch.com/de і bosch.com/ua - різні компанії). Точний збіг адреси блокується, той самий домен з іншим шляхом - лише попередження. Джерело, яке вже відстежується в іншій компанії, позначається у списку знахідок.
21. **Формат CSV та імпорт** (розділ 10): один формат для експорту й імпорту - `company_name`, `company_url`, `career_url`, рядок на джерело. Компанія розпізнається за `company_url`, «неоднозначні відповідності» прибрано. Заповнений `career_url` - джерело додається одразу (Tracked), порожній - Not tracked (Not checked). Після імпорту - підсумок.
22. **Порядок етапів і процес розробки** (розділи 11, 14): парсинг перенесено перед пошуком кар'єрних сторінок, перша робоча версія - на етапі 3. Новий розділ 14: TDD для логіки, TDD на рівні етапу для E2E, три рівні тестів (Vitest, Vitest + PostgreSQL, Playwright Test), фейковий сервер замість справжніх сайтів.
23. **Репозиторій** (розділ 14): один репозиторій з одним Next.js-застосунком - фронтенд і бекенд разом, розведені по папках. Мультипакетний монорепозиторій не потрібен.
24. **Мова** (розділ 14): документація й коментарі - українською. Коміти (Conventional Commits), назви в коді, назви тестів і логи - англійською.
25. **Маленькі кроки з поясненнями** (розділи 11, 14): кожен етап - маленькими кроками, один крок - один коміт. Перед кроком - пояснення і очікування «ок», після - що змінилося, як перевірити, текст коміту. Правила переносяться в `CLAUDE.md` на етапі 1.
26. **Задачі в Trello** (розділ 14): дошка JobDigger з колонками Analyze, Backlog, To Do, In Progress, Testing, Done. Картка - задача з чеклістом кроків; етап зазначений першим рядком опису. Картки створюються після погодження списку, у Done - лише після перевірки автором. **Замінено 17.11.2026:** задачі переїхали у файли `tasks/` зі статусами в таблиці `tasks/README.md`, бо робота з дошкою через MCP коштувала забагато токенів; Trello лишився архівом завершених карток.
27. **GitHub Flow** (розділи 11, 14): гілка на картку, коміт на крок, PR з описом українською, рев'ю і squash merge робить автор, тести в GitHub Actions на кожен PR. Репозиторій на GitHub і доступ - на етапі 1.
28. **Скіли** (розділи 11, 14): `vercel-react-best-practices`, `tdd`, `heroui-react`, `grill-me` - на етапі 1, `neon-postgres` - на етапі 7. Лише в проєкт, через `npx skills add`, з читанням `SKILL.md` перед встановленням. Не беремо: Drizzle, Playwright, Next.js, Feature-Sliced Design, Git Commit, Ponytail, agent-browser, find-skills. Після етапу 1 - прогін плану через Grill Me.
29. **Дрібниці** (розділи 2, 14): HeroUI v3 стабільна (3.2.x). Дві мови з першої версії - лише для інтерфейсу (next-intl, тест на однакові ключі, за замовчуванням English). Дані із сайтів не перекладаються.
30. **Фінальна перевірка узгодженості** (розділи 4.2, 4.3, 5, 6, 8, 9, 12, 13, Підсумок): прибрано залишки старих рішень (ліміт сторінок у ризиках, описи вакансій, коренева URL, «пошук альтернатив»), виняток для Favorites при порожньому API, ручні перевірки - з урахуванням правил перетину. Додано статуси компаній на Tracked (OK, Has errors, Checking), правило черги для Find new pages, завдання поза History. Версія - v1.3.0, план затверджено.
