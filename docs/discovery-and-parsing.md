Частина технічного плану Job Digger v1.4.0. Карта всіх файлів - у [README](README.md).

## 5. Додавання компанії та пошук кар'єрних сторінок

Сценарій уже в коді:

- модалка Add company, Find pages, вибір знахідок, Save і перша перевірка - [`src/app/README.md`](../src/app/README.md#додавання-компанії);
- три способи пошуку (посилання з сайту на ATS, кар'єрні сторінки сайту, ATS за назвою), перевірка належності й пробне читання - [`src/server/discovery/README.md`](../src/server/discovery/README.md);
- адреса компанії зі шляхом (bosch.com/de і bosch.com/ua - різні компанії) і правила дублікатів - [`src/lib/companies/README.md`](../src/lib/companies/README.md) і [`src/server/companies/README.md`](../src/server/companies/README.md).

Правила, яких поки немає в README поруч із кодом:

- Пошук джерел виконується при додаванні будь-якого типу URL, навіть якщо користувач уже надав готову кар'єрну сторінку.
- У регулярних перевірках вакансій глобальний пошук кар'єрних сторінок не повторюється.
- Зовнішній пошуковий API в першій версії не використовується ([розділ 12](roadmap.md)). Якщо джерело не знайдено, кар'єрну адресу можна вставити вручну в тому самому модальному вікні.

## 6. Парсинг вакансій

Парсери ATS, спільний формат результату, ліміт вакансій і глибина читання, власна сторінка за рецептом - [`src/server/parsers/README.md`](../src/server/parsers/README.md). Ввічливість до сайтів, тайм-аут, ліміт розміру й повтори - [`src/server/http/README.md`](../src/server/http/README.md). Що робить із вакансіями успішна чи невдала перевірка - [`src/server/vacancies/README.md`](../src/server/vacancies/README.md#життєвий-цикл).

Ще не зроблено:

- **Структуровані дані сторінки (schema.org JobPosting)** - другий спосіб читання після API платформи. Відкладено до джерела, якому він потрібен (задача [3.11](../tasks/3.11-schema-org-jobposting-parser.md)). Нуль вакансій зі сторінки вважатиметься збоєм, а не порожнім списком: найімовірніше, змінилася верстка. Нумерована пагінація та Next на довільних HTML-сторінках потрібні лише цьому парсеру.
- **Браузерний парсинг через Playwright** у першій версії не використовується. Його додамо, лише якщо трапиться важливий сайт, якому він справді потрібен. Load more і динамічне підвантаження відкладаються разом із ним.
- Можливі розширення пізніше: універсальний пошук посилань на вакансії, витягування вакансій за допомогою ШІ.

## 7. Життєвий цикл вакансії

Ключ, очищення адреси, життєвий цикл, Closed, дублікати між джерелами, позначки користувача й одночасні зміни - [`src/server/vacancies/README.md`](../src/server/vacancies/README.md).

Правила, яких поки немає в README поруч із кодом:

- Description, salary та employment type не зберігаються. Компанія і source URL беруться через зв'язок «вакансія → джерело → компанія» і окремо не зберігаються.
- Дії користувача ніколи не змінюють назву чи URL вакансії: оновлюються лише потрібні колонки, а не весь запис.
