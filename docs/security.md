# Job Digger - Безпека

Частина технічного плану Job Digger v1.4.0. Карта всіх файлів - у [README](README.md).

## 13. Безпека

### Локально (без входу)

1. **Сервер доступний лише з цього комп'ютера.** За замовчуванням `next dev` слухає всю мережу (0.0.0.0), тому застосунок запускається з `-H 127.0.0.1`.
2. **Захист від чужих сайтів (CSRF).** Усі зміни даних виконуються через Server Actions - Next.js перевіряє, що запит прийшов із нашої сторінки. Якщо знадобляться звичайні API-маршрути, така сама перевірка Origin додається вручну.

### Запити до чужих сайтів

3. **Лише публічні адреси (захист від SSRF).** Сервер ходить за URL від користувачів і знайденими парсером (посилання, sitemap, редиректи). Дозволені тільки http/https. Внутрішні адреси заборонені: localhost, приватні мережі (192.168.x.x, 10.x.x.x тощо), зокрема після редиректів. Для кожного запиту - тайм-аут і ліміт розміру відповіді.
4. **Вміст із сайтів - лише як текст.** Назви та локації вакансій показуються як текст, не як HTML. URL вакансій приймаються тільки з http/https. Посилання відкриваються в новій вкладці з `rel="noopener noreferrer"`.
5. **CSV-експорт без формул.** Значення, що починаються з `=`, `+`, `-` або `@`, екрануються, щоб Excel не виконав їх як формули.

### Онлайн

6. **Усе - лише після входу.** Виняток - обробник розкладу і перезапуск черги. Вони захищені секретним ключем з ENV, щоб сторонні не могли запускати перевірки.
7. **Секрети - лише в ENV:** ключі Google, `DATABASE_URL`, секрет обробника. Файли `.env*` не потрапляють у git.
8. **Email зі списку дозволених перевіряється на кожному запиті**, а не лише при вході. Якщо прибрати email з ENV, доступ зникає одразу.
