## 4. Структура застосунку

**Jobs** (Default)

Unread · Read · Favorites · All

**Companies**

Tracked · Not tracked

**History**

**Settings**

### 4.1. Jobs

Порядок вкладок фіксований:

(Unread) (Read) (Favorites) (All)

За замовчуванням відкривається **Unread**.

- **Unread:** активні вакансії, ще не позначені як прочитані.
- **Read:** активні прочитані вакансії.
- **Favorites:** вакансії з позначкою Favorite, зокрема ті, що зникли з сайту (позначка Closed).
- **All:** усі активні вакансії незалежно від статусу.

Для кожної вакансії показуємо назву, компанію, локацію та дату виявлення.

Дії: Mark as Read / Mark as unread (перемикач), Favorite / Remove from Favorites, відкриття оригінальної вакансії в новій вкладці.

У вкладці Unread є кнопка **Mark all as read**. Вона позначає прочитаними всі вакансії у вкладці, по всіх компаніях. Перед виконанням показується діалог підтвердження з кількістю вакансій (наприклад, «Позначити 243 вакансії як прочитані?»). Діалог підтвердження є лише для цієї загальної дії.

Відкриття URL не змінює статус Read.

Не додаємо фільтри за компанією, локацією чи типом зайнятості. Експорту вакансій немає.

Фільтра за ключовими словами під час збереження теж немає - зберігаються всі вакансії джерела. Основний сценарій - невеликі компанії.

Кількість непрочитаних вакансій показується в меню біля Jobs і в назві вкладки браузера (наприклад, «(12) Job Digger»). Інших сповіщень (Telegram, email, сповіщень браузера) немає.

### 4.2. Companies - Tracked

Сторінка Companies має дві вкладки - Tracked і Not tracked - з кількістю компаній у назві (наприклад, «Tracked (120)»). Кнопка Add і модальне вікно додавання розміщені на цій сторінці.

Вкладка Tracked - основний список компаній, для яких є щонайменше одна кар'єрна сторінка, що відстежується. На ній є кнопка Check all - загальна перевірка вакансій ([розділ 8](checks-and-queue.md)).

Для кожної компанії показуємо її назву, головний сайт, кар'єрні джерела, кількість активних вакансій, статус та час останньої перевірки.

Статус компанії: **OK** - остання перевірка без помилок, **Has errors** - є невдалі джерела, **Checking** - зараз перевіряється.

Дії: Add, Edit, Check now, Mark all as read, Mark all as unread, Delete через іконку кошика.

Mark all as read / Mark all as unread змінюють статус усіх активних вакансій цієї компанії. Діалогу підтвердження немає - дію легко скасувати протилежною.

Delete видаляє компанію повністю - разом з усіма її джерелами і вакансіями, зокрема з Favorites. Видалення підтверджується діалогом з попередженням (наприклад, «Буде видалено 14 вакансій, з них 2 у Favorites»). Історична агрегована статистика залишається.

Окреме джерело прибирається через Edit: у модальному вікні є список джерел компанії з кнопкою видалення. Якщо прибрати останнє джерело, компанія переходить у Not tracked зі статусом Not checked.

Не створюємо окрему сторінку деталей джерела чи додатковий складний механізм багаторівневого видалення.

### 4.3. Companies - Not tracked

Вкладка зі списком компаній, для яких немає джерела, що відстежується.

Можливі стани:

- **Not checked** - ще не перевірено (наприклад, після імпорту CSV).
- **Not found** - кар'єрну сторінку не знайдено.
- **Unsupported** - сторінку знайдено, але вона не підтримується. Адреса зберігається - знадобиться, якщо пізніше з'являться нові способи читання.
- **Check failed** - помилка перевірки.

Дії: Find pages для однієї компанії, Find new pages для всього цього списку, Edit і Delete.

**Find pages** відкриває для однієї компанії те саме модальне вікно зі списком знахідок, що й під час додавання ([розділ 5](discovery-and-parsing.md)). Користувач сам обирає джерела.

**Find new pages** у фоні повторює пошук кар'єрних сторінок для всіх компаній вкладки, з пробним читанням знахідок:

- автоматично додаються лише надійні знахідки, які читаються: посилання з сайту компанії на ATS і кар'єрна сторінка на її сайті. Компанія з такою знахідкою переходить на вкладку Tracked;
- знахідки лише «за назвою» автоматично не додаються. Компанія лишається в Not tracked з підказкою «Є можлива сторінка - перевір», а вибір підтверджується через Find pages;
- якщо нічого не знайдено, статус оновлюється: Not found, Unsupported або Check failed.

Завдання Find new pages ідуть у ту саму чергу зі спільним лімітом 5, тож можуть виконуватися паралельно з Check all. Повторно запустити Find new pages, поки триває попередній запуск, не можна.

Ці компанії **ніколи не беруть участі у звичайному Check all чи автоматичних перевірках вакансій**.

### 4.4. History

Один рядок - одна завершена загальна перевірка.

Зберігаємо рівно п'ять показників:

| Поле              | Значення                                                  |
| ----------------- | --------------------------------------------------------- |
| Date & time       | Час запуску                                               |
| Sources checked   | Кількість джерел, включених у перевірку, зокрема невдалих |
| New vacancies     | Кількість нових вакансій                                  |
| Removed vacancies | Кількість прибраних вакансій                              |
| Duration          | Тривалість перевірки                                      |

Жодних детальних логів або переліків вакансій у History. Check now і Retry в History не записуються - лише загальні перевірки.

Спочатку завантажуємо 20 записів. **Load more** додає наступні 20. Історія зберігається без обмеження строку.

### 4.5. Settings

Особисті налаштування користувача: інтервал автоматичної перевірки, мова, імпорт/експорт CSV.

Паралельність і ліміти сторінок - спільні налаштування сервера. Вони задаються через ENV і в Settings не показуються.

Інтервал автоматичної перевірки вибирається зі списку: 3, 6, 12 або 24 години. За замовчуванням - 6 годин. Інтервал - особисте налаштування кожного користувача.

## 10. CSV Import / Export

Обидві функції розміщуються тільки в Settings.

### Формат файлу

Один формат для експорту й імпорту, тож експортований файл можна імпортувати назад (наприклад, з локальної версії в онлайн). Колонки: `company_name`, `company_url`, `career_url`.

```csv
company_name,company_url,career_url
Acme UA,acme.com/ua,https://boards.greenhouse.io/acme
Beta,beta.io,
```

- Один рядок - одне джерело. Компанія з кількома джерелами займає кілька рядків з однаковим `company_url`.
- Компанія без джерел - один рядок із порожнім `career_url`.

### Export CSV

**Export options**

- **Tracked** - включити компанії з вкладки Tracked.
- **Not tracked** - включити компанії без джерел, що відстежуються.
- **Include career page URLs** - додати кар'єрні URL.

Кнопка **Export CSV** завантажує CSV відповідно до вибраних опцій.

За замовчуванням вибрані Tracked і Not tracked. Третя опція вимкнена.

Без третьої опції колонка `career_url` порожня - один рядок на компанію. Із третьою - заповнена, по рядку на кожне джерело. Формат файлу не змінюється.

Якщо не вибрано жодного списку, Export CSV вимкнена.

### Import CSV

Компанія розпізнається за `company_url` за правилами дублікатів із [розділу 5](discovery-and-parsing.md). Джерело прив'язується до компанії свого рядка, тому неоднозначних відповідностей немає.

- Якщо компанія вже існує, копія не створюється. Нові `career_url` додаються до наявної компанії.
- Якщо `career_url` заповнено, джерело додається одразу, а компанія потрапляє в Tracked. Вакансії підтягуються під час найближчої перевірки.
- Якщо `career_url` порожній, компанія потрапляє в Not tracked зі статусом Not checked. Масовий пошук після імпорту автоматично не запускається.
- Після імпорту показується підсумок (наприклад, «Додано 25 компаній і 40 джерел, пропущено 3 дублікати, 2 рядки з помилкою (невалідна URL)»).
