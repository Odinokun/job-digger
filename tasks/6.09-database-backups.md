# 6.09 Резервні копії робочої бази

**Етап 6 — Автоматизація та Settings** · інфраструктура

Брати після 6.08.

Усі дані робочого екземпляра лежать в одному Docker volume. `docker compose down -v`, видалений том чи зламаний Docker стирають усе, зокрема Read/Favorite, які з сайтів уже не відновити.

Що зробити:

- `pg_dump` робочої бази у файл з датою в назві (інструмент уже є в образі `postgres`, нова залежність не потрібна);
- запуск за розкладом або на старті робочого екземпляра - вирішити на старті задачі; Mac працює не постійно, тож розклад на конкретну годину може пропускатися;
- скільки копій тримати і куди класти (локальна тека чи синхронізована з хмарою) - рішення автора на старті задачі;
- перевірена процедура відновлення (`pg_restore` у порожню базу) - копія, яку ніхто не відновлював, нічого не гарантує;
- документація: де лежать копії, як відновити.

`pg_dump` / `pg_restore` - той самий шлях, що й перенесення даних у Neon (7.06).

**Повернулися 20.11.2026** разом із 6.08: робочий екземпляр - окремий `git clone` у `~/code/job-digger-app`, база `job_digger_app` у тому самому контейнері, запуск `npm run app` (README, розділ «Робочий екземпляр»).
