# 4.03 Обробник черги як фоновий цикл

**Етап 4 — Черга та перевірки**

Брати перед 4.04.

Локально обробник працює як фоновий цикл усередині сервера Next.js і стартує разом із `npm run dev`. Одночасно виконується не більше 5 джерел — ліміт спільний для всіх користувачів, задається через ENV (діапазон 1–10).

Черга зберігається в БД, а не в оперативній пам'яті: це дає відновлення після помилок і незалежність від відкритого браузера. Сторонні сервіси для черги не потрібні, код обробника однаковий локально й на Vercel.

План: docs/overview.md розділ 3.

**З рев'ю 1.13:** два рівні пріоритету — ручні завдання (Find pages, Check now, Retry) беруться раніше за фонові (Check all, Find new pages, автоперевірка). Ліміт п'яти одночасних джерел лишається спільним, тож ручна дія чекає щонайбільше одне фонове завдання, а не всю чергу з 300 (docs/checks-and-queue.md розділ 8).
