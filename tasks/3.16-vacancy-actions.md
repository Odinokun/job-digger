# 3.16 Дії над вакансією

**Етап 3 — Парсинг і вакансії**

Перемикач Mark as Read / Mark as unread, Favorite / Remove from Favorites, відкриття оригінальної вакансії в новій вкладці.

Правила: відкриття URL **не** змінює статус Read. Посилання відкриваються з `rel="noopener noreferrer"`, назви й локації показуються як текст, не як HTML. URL приймаються тільки з http/https.

Вакансія з позначкою Closed видаляється, коли користувач прибирає її з Favorites (перенесено з 3.13). Робити однією умовною командою, як прибирання зниклих у `src/server/vacancies/lifecycle.ts`: якщо перевірка саме зняла Closed, бо вакансія повернулася, видаляти не можна - лише прибрати Favorite.

План: docs/ui.md розділ 4.1, docs/discovery-and-parsing.md розділ 7, docs/security.md розділ 13, пункт 4.

Остання задача на шляху до зеленого 3.20: наприкінці зняти тег `@pending` з `e2e/vacancies.spec.ts` - сценарій стає звичайним і далі йде в CI.

## Рішення (18.11.2026)

- Межа тестування - `setVacancyRead`, `setVacancyFavorite` і `findVacancy` у `src/server/vacancies/marks.ts` (інтеграційні тести) і `belongsToJobsTab` у `src/lib/vacancies/` (юніт-тести).
- Кожна дія змінює лише своє поле й повертає оновлений рядок списку; `null` - вакансії вже немає, рядок прибирається без помилки. Криве id з клієнта - `null`, а не помилка бази.
- Remove from Favorites для закритої вакансії: у транзакції `delete ... where closed_at is not null`, потім `update is_favorite` - рішення за поточним станом рядка, тож вакансія, яку перевірка саме знову відкрила, лишається.
- Кнопки - іконки з `aria-label`, що каже дію; без `aria-pressed`, бо підпис і так змінюється. Непрочитана вакансія - жирніша назва.
- Без оптимістичного оновлення: кнопка в `isPending` до відповіді. Оптимізм із відкатом - 3.21.
- `npm run test:e2e:pending` між етапами дає «No tests found» - залишено свідомо, без `--pass-with-no-tests`.
