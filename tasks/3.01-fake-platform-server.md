# 3.01 Фейковий сервер із відповідями платформ

**Етап 3 — Парсинг і вакансії** · тестова інфраструктура

Брати перед 3.20.

Локальний фейковий сервер зі збереженими реальними відповідями платформ. Тести **ніколи** не ходять на справжні сайти. Для кожного парсера зберігається файл із реальною відповіддю платформи.

Робиться першим в етапі, бо на нього спираються всі парсери.

План: docs/process.md розділ 14 («Тести і TDD»).

## Що вирішити до коду

Фейковий сервер потрібен не лише юніт-тестам парсерів, а й E2E 3.20, де на платформу ходить сервер застосунку, а не браузер. Звідси два питання, від яких залежить, як писатимуться всі парсери (3.06-3.11):

- **Підміна адреси платформи.** Як парсер іде на фейковий сервер замість справжнього `boards-api.greenhouse.io` - і в юніт-тестах, і в застосунку, запущеному для E2E.
- **Виняток у захисті від SSRF (3.03).** Фейковий сервер живе на `127.0.0.1`, яку SSRF забороняє. E2E працюють на продакшн-збірці (`next start`), тож «тестовий режим» не можна визначати через `NODE_ENV=test` - потрібен явний виняток рівно для однієї адреси, безпечний, навіть якщо змінна випадково потрапить у продакшн.

**Рішення 18.11.2026:** запити застосунку потрапляють на фейковий сервер через одну точку підміни в HTTP-модулі (3.02), а не через параметри парсерів. Деталі й відкинуті варіанти - [src/server/http/testing/README.md](../src/server/http/testing/README.md).
