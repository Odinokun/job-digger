# 7.09 Пін GitHub Actions і Dependabot

**Етап 7 — Підготовка до Vercel** · інфраструктура, тестів не має

У `.github/workflows/ci.yml` сторонні actions підключені за рухомим мажорним тегом (`actions/checkout@v7`, `actions/setup-node@v7`, `actions/cache@v6`). Тег можна переставити: «a tag can be moved or deleted if a bad actor gains access to the repository storing the action» ([secure-use](https://docs.github.com/en/actions/reference/security/secure-use)).

Чому саме етап 7: зараз токен прогону має лише `contents: read` і справжніх секретів у CI немає. Вони з'являються разом із рядком підключення до Neon і токенами Vercel — тоді ціна перехопленого прогону стає реальною.

**Кроки:**

- прочитати https://docs.github.com/en/actions/concepts/security/workflow-dependency-lockfiles — новий механізм GitHub, який, за їхніми словами, «supersedes SHA pinning»;
- якщо lockfile не підходить — пін на повний commit SHA: «they would need to generate a SHA-1 collision for a valid Git object payload»;
- при піні на SHA додати Dependabot, бо автоматичних патчів більше не буде;
- перевірка: прогін CI на PR лишається зеленим.
