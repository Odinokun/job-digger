# 3.21 Стани завантаження й оптимістичні дії

**Етап 3 — Парсинг і вакансії** · робити разом із 3.15 і 3.16

Знахідка рев'ю 1.13: у плані не було ні слова про стани завантаження, хоч із пагінацією і polling їх кілька — перше завантаження списку, Load more, Mark as read і Favorite на рядку, Check now.

**Кроки:**

- `loading.tsx` зі skeleton для Jobs, Companies і History;
- spinner у кнопці Load more;
- Mark as read і Favorite застосовуються оптимістично й відкочуються, якщо Server Action повернув `error` — разом із toast із задачі 2.09;
- ручна перевірка: дія при зупиненій базі повертає рядок у попередній стан і показує повідомлення.

План: docs/ui.md розділ 4 («Очікування»).

## Рішення (18.11.2026)

- Оптимізм - `useOptimistic` у `src/app/_jobs/jobs-board.tsx` з чистою функцією `patchVacancy` (`src/lib/vacancies`, юніт-тести). Справжній список оновлюється лише при успіху, тож при збої React сам повертає попередній стан; сповіщення - той самий `useActionFailedToast`.
- Рядок, який дія вивела з вкладки, зникає одразу (фільтр `belongsToJobsTab` по оптимістичному списку) і повертається при збої.
- `isPending` у HeroUI `Button` лише вимикає кнопку - спінер малюємо самі за прикладом Loading із документації. Зроблено для Load more (Jobs, Companies) і Check now; кнопки модалок поки без спінера.
- `loading.tsx` - для Jobs і Companies. History поки не читає даних - її заготовка переїхала в 4.10.
- Ручна перевірка відкату - тимчасовим E2E: посеред тесту база E2E видаляється (`dropdb --force`), Mark as read повертає рядок і показує сповіщення.
