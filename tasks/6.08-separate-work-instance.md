# 6.08 Окремий робочий екземпляр застосунку

**Етап 6 — Автоматизація та Settings** · інфраструктура, тестів не має

Брати перед тим, як автор почне заповнювати застосунок справжніми компаніями.

Рішення автора 20.11.2026: застосунком починаємо користуватися щодня локально, ще до етапу 7. Зараз є одна база розробки, і в ній ручні тестові записи (Acme, дві Linear тощо), а міграції з незлитих гілок застосовуються саме до неї. Справжні дані там жити не можуть.

Що зробити:

- окрема робоча база в тому самому контейнері PostgreSQL (база розробки і тестові лишаються як є);
- робочий екземпляр - продакшн-збірка (`next build` + `next start -H 127.0.0.1`) на окремому порту, щоб `npm run dev` не заважав і не ділив із ним порт;
- окремий набір змінних середовища для робочого екземпляра. Як `next start` вибирає `.env*`-файли - звірити з документацією в `node_modules/next/dist/docs/`, не з памʼяті;
- процедура оновлення після merge у `main`: оновити код, `npm ci`, міграції на робочу базу, збірка, перезапуск. Бажано однією командою (npm-скрипт), щоб не забути міграцію;
- документація: як запустити, як оновити, де яка база.

Два обробники черги (dev і робочий) працюють кожен зі своєю базою, тож одне одному не заважають. Ліміт ввічливості до сайтів у них свій - це прийнятно, бо розробка ходить на справжні сайти рідко.

**Відкладено, потім повернулися (20.11.2026).** Поки справжніх даних не було, працювали в одній теці й одній базі. Після решти етапу 6 автор вибрав спосіб розподілу з трьох: окрема тека через `git worktree`, окремий `git clone` або та сама тека з окремою базою. Вибір - **`git clone`**: звичайний репозиторій на `main`, оновлення - `git pull`. Worktree відкинуто, бо одну гілку не можна взяти у двох теках одночасно, і робоча тека на `main` заважала б `git checkout main` у теці розробки (обхід через `--detach` робочий, але зайвий). Та сама тека - бо робочий застосунок не перезапустити, поки тека на feature-гілці.

Як це вийшло в коді:

- окремий набір змінних - просто `.env` у теці клону, тож `.env.production` і порядок завантаження `.env*` (`node_modules/next/dist/docs/01-app/02-guides/environment-variables.md`) не знадобилися;
- база створюється один раз `createdb` у наявному контейнері;
- скрипти `npm run app` (порт 3100) і `npm run app:update` (лише на `main`: pull, `npm ci`, міграції, збірка).
