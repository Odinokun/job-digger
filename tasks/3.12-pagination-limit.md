# 3.12 Пагінація з лімітом 5 сторінок

**Етап 3 — Парсинг і вакансії** · строго TDD

Підтримка пагінації API платформ, нумерованої пагінації та кнопки Next на сторінках. Load more і динамічне підвантаження — відкладено разом із Playwright.

`Pages to check = 5` (через ENV). Досягнення ліміту — **нормальне завершення**, перевірка вважається успішною.

Відомий ризик: якщо сайт сортує не за датою, вакансія може випасти за межі перших сторінок, бути видаленою і пізніше повернутися як нова Unread. Прийнятно.

План: docs/discovery-and-parsing.md розділ 6.

**З 3.07:** Lever уже читає сторінками з лімітом - параметр `maxPages` (5) у `readLever` (`src/server/parsers/lever.ts`). Тут лишається зробити ліміт налаштуванням через ENV і підключити до нього Lever, а також нумеровану пагінацію й Next на HTML-сторінках.

**З 3.09:** Workday теж читає сторінками - `maxPages` (5) у `readWorkday` (`src/server/parsers/workday.ts`), по 20 вакансій, тобто щонайбільше 100 з джерела. Для великих компаній (NVIDIA - понад 2000) це помітно мало: варто подумати, чи не потрібен окремий ліміт для API платформ проти HTML-сторінок.

**З 3.10:** PeopleForce читає HTML-сторінки `?page=N` за посиланням `rel="next"` - `maxPages` (5) у `readPeopleForce` (`src/server/parsers/peopleforce.ts`), по 10 вакансій, тобто щонайбільше 50. Це вже нумерована пагінація на сторінках, про яку ця задача.
