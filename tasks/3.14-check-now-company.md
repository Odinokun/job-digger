# 3.14 Check now для однієї компанії

**Етап 3 — Парсинг і вакансії**

Брати перед 3.15.

Кнопка Check now на сторінці Companies: перевіряє всі джерела однієї компанії і застосовує життєвий цикл вакансій. Поки без черги — її робимо на етапі 4.

Check now у History не записується.

План: docs/ui.md розділ 4.2, docs/checks-and-queue.md розділ 8.

## Рішення (18.11.2026)

- Межа тестування - `checkCompany(db, client, { userId, companyId, checkedAt })` у `src/server/checks/`, інтеграційні тести на справжній базі й фейковому вебсервері.
- Нова колонка `career_sources.last_checked_at` (міграція `0006_source_last_checked`): «Last checked» показує найпізнішу перевірку серед джерел компанії.
- Перевіряються лише джерела, що відстежуються й мають парсер (`parsers/read-source.ts`); решта пропускається мовчки, а не рахується невдалою.
- Компанію чи джерело видалили посеред перевірки - результат відкидається: `syncSourceVacancies` блокує рядок джерела `FOR KEY SHARE`.
- Server Action синхронна: кнопка в `isPending`, доки читаються джерела.
- Спільне «зараз» для відносного часу задає `src/i18n/request.ts`, щоб серверний і клієнтський текст збігалися.
- Неактивність Check now під час загальної перевірки - разом із чергою (етап 4): загальних перевірок ще немає.
