# 3.04 Схема vacancies

**Етап 3 — Парсинг і вакансії**

Таблиця `vacancies`: внутрішній ключ, title, URL, location, first detected, last checked, статус Unread/Read, Favorite, позначка Closed. Зв'язок із `career_sources`.

Компанія і source URL беруться через зв'язок «вакансія → джерело → компанія» і окремо не зберігаються. Description, salary та employment type не зберігаються.

План: docs/data.md розділ 9, docs/discovery-and-parsing.md розділ 7.

**Борг із картки 2.06 (рішення 17.11.2026).** Діалог видалення компанії зроблений **без чисел**, бо на етапі 2 вакансій не існувало. Коли ця таблиця з'явиться, треба повернутися в діалог Delete і дописати попередження з числами: «Буде видалено 14 вакансій, з них 2 у Favorites» (docs/ui.md розділ 4.2). Логіка каскадного видалення вже написана в 2.06 — потрібен лише підрахунок для тексту.
