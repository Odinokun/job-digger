# 3.13 Життєвий цикл вакансії

**Етап 3 — Парсинг і вакансії** · строго TDD + інтеграційні тести

Брати перед 3.14.

Найтонше місце плану. Правила:

| Подія | Дія |
| --- | --- |
| З'явилася вперше | Створити як Unread |
| Знайдена повторно | Оновити last checked, зберегти Read/Favorite |
| Змінилася назва | Оновити назву, зберегти Read/Favorite |
| Змінилася URL, є ID платформи | Оновити URL |
| Змінилася URL, ID немає | Старий запис видалити, новий створити як Unread |
| Зникла після успішної перевірки | Видалити. Якщо у Favorites — залишити з позначкою Closed |
| Зникла і повернулася | Показати як нову Unread |
| Перевірка з помилкою | Не видаляти вакансії цього джерела |

Вакансія з позначкою Closed видаляється, коли користувач прибирає її з Favorites.

Одночасні зміни: кожна сторона змінює лише свої поля; видалення зниклих — однією командою з умовою щодо Favorites, щоб щойно додана у Favorites вакансія не загубилася.
