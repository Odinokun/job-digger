# 3.05 Очищення URL і внутрішній ключ вакансії

**Етап 3 — Парсинг і вакансії** · строго TDD

Брати перед 3.13.

Ключ вакансії: джерело + ID вакансії на платформі. Якщо ID немає — джерело + очищена URL: без міток відстеження (`utm_*`, `gh_src`), без слеша в кінці.

Усередині одного джерела повторні записи не створюємо. Між різними джерелами дублікати не об'єднуємо.

План: docs/discovery-and-parsing.md розділ 7.

## Рішення (18.11.2026)

- Код - `src/server/vacancies/key.ts`, юніт-тести. Межі тестування: `cleanVacancyUrl(url)` і `vacancyKey({ externalId, url })`.
- Мітки, що прибираються: `utm_*`, `gh_src`, `gh_jid`, `fbclid`, `gclid`. Решта параметрів лишається й сортується.
- `vacancyKey` приймає `{ externalId: string | null; url: string }`, а не тип парсера: у schema.org (3.11) ID може не бути.

## Кроки

- [x] `cleanVacancyUrl`: без міток, якоря й слеша в кінці, параметри впорядковані
- [x] `vacancyKey`: `id:<ID>` або `url:<очищена адреса>`
