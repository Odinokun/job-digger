# Change list не на картці, поки рецепт працює

**Поза етапами — UI** · правило показу за TDD, верстка - знімки до і після

Знахідка автора 22.11.2026. На картці компанії з власною сторінкою (Own page) під адресою завжди стоїть кнопка Change list (задача 6.21, [docs/ui.md](https://github.com/Odinokun/job-digger/blob/plan-v1.4.0/docs/ui.md), розділ 4.3.1). Коли рецепт уже вибрано і сторінка читається, кнопка зайва: вона велика, і при прокручуванні списку здається, що компанія чекає якоїсь дії. На картці дія має бути лише тоді, коли є проблема - як Read as list і Link only у сторінки Unsupported.

## Пропозиція (ще не рішення)

Change list показується на картці лише тоді, коли власна сторінка впала (`lastCheck === "failed"`). Порожній результат за рецептом - уже збій `unreadable`, а не закриття всіх вакансій (6.21), тож зламаний рецепт сам дає Has errors, і кнопка з'являється саме там, де треба. У решті випадків Change list живе в модалці Edit - у рядку джерела, поруч із кошиком.

Альтернативи:

- **Лише в Edit** (ідея автора): найпростіше, але коли сайт переробили, картка покаже Has errors без підказки, що робити далі.
- **Лишити на картці, але тихо:** іконка з підказкою замість кнопки з текстом. Менше шуму, але дія видна завжди.

## Що вирішити на старті

- Яку з механік беремо.
- Change list у Edit - друга модалка поверх Edit чи вибір груп прямо в рядку джерела. Чи HeroUI v3 підтримує модалку в модалці - перевірити в документації.
- Картка знає лише `ok` / `failed`, без причини: Change list з'явиться і при мережевому збої, коли рецепт ще правильний. Досить цього чи зберігати причину збою.
- Read as list у сторінки, позначеної Link only, - той самий шум? Позначка вже означає «рішення ухвалено».
