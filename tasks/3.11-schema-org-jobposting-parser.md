# 3.11 Парсер schema.org JobPosting

**Етап 3 — Парсинг і вакансії** · строго TDD

Друга стратегія після API: структуровані дані сторінки (schema.org JobPosting) через Cheerio.

Критичне правило: **нуль вакансій зі сторінки вважається збоєм**, бо найімовірніше змінилася верстка. Вакансії в такому разі не видаляються. Нуль із API платформи — навпаки, достовірний результат.

Власні сторінки без стандартної розмітки — статус Unsupported.

План: [docs/discovery-and-parsing.md](https://github.com/Odinokun/job-digger/blob/plan-v1.4.0/docs/discovery-and-parsing.md) розділ 6.

## Відкладено (18.11.2026)

Рішення автора: парсери, яких ще немає, додаємо тоді, коли трапиться справжнє джерело, якому вони потрібні. Поки задача в `backlog`.

Що з'ясувалося до відкладення - знадобиться, коли до задачі повернемося:

- **Google забороняє JobPosting на сторінках-списках.** «The `JobPosting` markup must only be used on pages that contain a single job posting» і «Don't add structured data to pages intended to present a list of jobs» ([документація](https://developers.google.com/search/docs/appearance/structured-data/job-posting)). Кар'єрні джерела, які ми відстежуємо, - саме списки, тож розмітку на них знайти майже не вийде.
- Перевірено 18.11.2026: на сторінках вакансій Mozilla, Altenar і Betterme (компанії з бази автора) JobPosting немає ні в JSON-LD, ні в microdata. Немає її й на сторінках окремих вакансій Greenhouse і PeopleForce.
- Отже, робочий варіант, найімовірніше, інший: зі сторінки-списку брати посилання на вакансії, а JobPosting читати на кожній сторінці вакансії. Це N запитів із паузою 2 с на одне джерело - це треба продумати разом із лімітами (3.12) до початку роботи.
