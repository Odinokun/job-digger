# 3.17 Mark all as read у вкладці Unread

**Етап 3 — Парсинг і вакансії**

Кнопка у вкладці Unread позначає прочитаними всі вакансії вкладки по всіх компаніях. Перед виконанням — діалог підтвердження з кількістю: «Позначити 243 вакансії як прочитані?». Це єдина дія з діалогом підтвердження серед дій над вакансіями.

Правило одночасних змін: дія діє лише на вакансії, що були в списку на момент підтвердження. Знайдені пізніше лишаються Unread. Якщо вакансія зникла в момент дії — нічого не робимо, без помилки.

План: docs/ui.md розділ 4.1, docs/discovery-and-parsing.md розділ 7.

## Рішення (18.11.2026)

- **Межа - знімок ID, а не дата виявлення** (рішення автора). `first_detected_at` - момент старту перевірки, тож перевірка, що йде під час діалогу, вставила б нові вакансії «заднім числом», і межа за датою мовчки зробила б їх прочитаними. Знімок береться в момент натискання (`listUnreadIds`), діалог показує його розмір, підтвердження позначає рівно ці ID (`markVacanciesRead`). Блокувати кнопку на час перевірки - відхилено: сервер до 4.01 не знає, що перевірка йде, а перевірка, що почалася вже при відкритому діалозі, лишила б ту саму гонитву.
- **Знімок іде на сервер порціями по 5000 ID** (`src/lib/vacancies/mark-all.ts`): тіло запиту Server Action - до 1 МБ, а після першої перевірки сотень компаній непрочитаних може бути десятки тисяч. Конфіг Next не змінюється.
- Порожній знімок (усе вже прочитано в іншій вкладці) - діалогу немає, список просто порожніє.
- Після успіху - `revalidatePath("/")`, як у 3.22.
