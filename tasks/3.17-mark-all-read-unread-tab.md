# 3.17 Mark all as read у вкладці Unread

**Етап 3 — Парсинг і вакансії**

Кнопка у вкладці Unread позначає прочитаними всі вакансії вкладки по всіх компаніях. Перед виконанням — діалог підтвердження з кількістю: «Позначити 243 вакансії як прочитані?». Це єдина дія з діалогом підтвердження серед дій над вакансіями.

Правило одночасних змін: дія діє лише на вакансії, що були в списку на момент підтвердження. Знайдені пізніше лишаються Unread. Якщо вакансія зникла в момент дії — нічого не робимо, без помилки.

План: docs/ui.md розділ 4.1, docs/discovery-and-parsing.md розділ 7.

## Рішення (18.11.2026)

- **Межа - `created_at`, а не дата виявлення** (рішення автора). `first_detected_at` - момент старту перевірки, тож перевірка, що йде під час діалогу, вставила б нові вакансії «заднім числом», і межа за датою мовчки зробила б їх прочитаними. Нова колонка `vacancies.created_at default now()` (міграція 0007) - момент запису рядка за годинником бази. `countUnread` дає кількість і межу (`now()` з мікросекундами), `markAllRead` - один атомарний `UPDATE` до межі.
- Залишкова гонитва - мілісекунди однієї транзакції запису джерела. Прийнятно.
- Перша версія PR робила знімок ID через браузер. Точний, але обʼєм ріс разом із кількістю непрочитаних (порції по 5000 під ліміт 1 МБ Server Action), а дія не була атомарною - автор вибрав переробити.
- Блокувати кнопку на час перевірки - відхилено: сервер до 4.01 не знає, що перевірка йде, а перевірка, що почалася при відкритому діалозі, лишила б ту саму гонитву.
- Непрочитаних уже немає (прочитали в іншій вкладці) - діалогу немає, список просто порожніє.
- Після успіху - `revalidatePath("/")`, як у 3.22.
