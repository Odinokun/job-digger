# 3.19 Лічильник непрочитаних вакансій

**Етап 3 — Парсинг і вакансії**

Кількість непрочитаних показується в меню біля Jobs і в назві вкладки браузера: «(12) Job Digger».

Інших сповіщень немає — ні Telegram, ні email, ні сповіщень браузера.

План: [docs/ui.md](https://github.com/Odinokun/job-digger/blob/plan-v1.4.0/docs/ui.md) розділ 4.1.

## Рішення (18.11.2026)

- Число - `countUnread` (`src/server/vacancies/marks.ts`, з 3.17): та сама умова, що вкладки Unread, тож Closed не входять. `getUnreadCount` у `src/app/components/unread-count.ts` загорнутий у `cache` React - один запит на рендер для шапки й назви вкладки.
- Меню: «Jobs (12)» у тому самому стилі, що «Tracked (5)» у Companies; нуль - без числа. Назва вкладки - `generateMetadata` кореневого layout.
- Шапка живе в кореневому layout, якого Next між переходами не перерендерює. Тому кожна дія, що змінює кількість непрочитаних, викликає `revalidateUnreadCount` - `revalidatePath("/", "layout")`: позначки вакансій, Mark all as read, Mark all as read / unread для компанії (3.18), Check now, видалення компанії, Edit (прибране джерело забирає вакансії).
- E2E `vacancies.spec.ts` перевіряє число в меню й назві вкладки після Check now, Mark as read і Mark all as read.
