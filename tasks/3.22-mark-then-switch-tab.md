# 3.22 Перехід на вкладку під час дії над рядком

**Етап 3 — Парсинг і вакансії** · баг 3.21, знайдений на CI PR #60

Mark as read, а одразу після нього клік на вкладку Read: вакансії в Read немає, і список сам не оновлюється. Те саме з Favorite і вкладкою Favorites. Причина в оптимізмі 3.21: рядок зникає з Unread одразу, ще до запису в базу, тож перехід встигає прочитати список до запису. На CI сценарій `e2e/vacancies.spec.ts` упав саме так (PR #60, запуск 44377647472); локально такого не було, бо дія встигала раніше.

## Рішення (18.11.2026)

- Read і Favorite після успішного запису викликають `revalidatePath("/")` (`src/app/_jobs/actions.ts`): у Server Function він оновлює сторінку, яку зараз видно, і скидає клієнтський кеш (`node_modules/next/dist/docs/01-app/03-api-reference/04-functions/revalidatePath.md`).
- E2E-сценарій затримує кожну Server Action на 1 с через `page.route` - гонитва стає детермінованою, а не залежить від швидкості машини. Без виправлення він червоний на кроці Read, з виправленням - зелений; із затримкою 3 с - теж зелений.
