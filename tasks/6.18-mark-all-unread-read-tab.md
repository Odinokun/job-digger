# 6.18 Mark all as unread у вкладці Read

**Етап 6 — Автоматизація та Settings** · логіка за TDD, UI без строгого

Привід (20.11.2026): автор, працюючи з робочим екземпляром, шукав на сторінці Jobs загальну Mark all as unread. Вона є лише на картці компанії (3.18), а загальна дія є тільки в один бік - Mark all as read у вкладці Unread (3.17).

**Рішення автора 20.11.2026:** кнопка у вкладці Read, дзеркально до 3.17 - повертає в Unread усі вакансії вкладки Read по всіх компаніях. Вкладки All і Favorites кнопки не мають.

Орієнтир - 3.17: діалог підтвердження з кількістю, один атомарний `UPDATE` до межі, без діалогу, якщо прочитаних уже немає, `revalidatePath("/")`.

На старті: яка межа для одночасних змін (у 3.17 - `created_at`, але вакансію, яку прочитали під час діалогу, позначає не перевірка, а людина - чи потрібна межа взагалі), чи потрібне правило з docs/ui.md про «єдину дію з діалогом підтвердження» переписати на дві.

План: docs/ui.md розділ 4.1.

## Рішення (20.11.2026)

- **Без межі** (рішення автора): `markAllUnread` - один `UPDATE` усієї вкладки Read. Перевірка у вкладку Read нічого не додає, а вакансія, прочитана в іншій вкладці браузера, поки відкритий діалог, теж має повернутися - саме цього людина й хотіла.
- Діалог 3.17 узагальнено: `_jobs/mark-all-read.tsx` → `_jobs/mark-all.tsx` з `target: "read" | "unread"`, щоб не дублювати розмітку `AlertDialog`.
- Правило docs/ui.md «діалог підтвердження лише для однієї загальної дії» стало «для двох».
