# 4.02 Захоплення завдань і повернення завислих

**Етап 4 — Черга та перевірки** · строго TDD + інтеграційні тести

Брати перед 4.03.

Серце черги. Два правила:

1. Обробник бере завдання з таблиці так, щоб **два процеси ніколи не взяли одне й те саме завдання**.
2. Якщо процес упав посеред перевірки, завдання через кілька хвилин повертається в чергу.

Ризик із плану: самої таблиці в БД недостатньо — потрібен надійний механізм запуску, повторного запуску і відновлення завислих завдань.

План: docs/overview.md розділ 3 («Принцип виконання»), docs/roadmap.md розділ 12.

**З рев'ю 1.13:** сюди ж фіналізація запуску і пріоритет у захопленні. Запуск закривається, коли не лишилося незавершених завдань, або після 15 хвилин без руху — з тими числами, які є; інакше перевірка, перервана сном комп'ютера чи вбитим сервером, блокує Check all і автоперевірки назавжди. Захоплення бере ручні завдання (Find pages, Check now, Retry) раніше за фонові (docs/checks-and-queue.md розділ 8).

## Кроки

Публічні межі - модуль `src/server/queue/`, кожна функція приймає базу й момент `now` ззовні.

- [x] `claimTask` - захоплення: пріоритет, вік, `for update skip locked`, ліміт одночасних
- [x] `finishTask` - результат завдання і лічильники запуску; пізній результат відкидається
- [x] `recoverStaleTasks` - завислі повертаються в чергу, після останньої спроби - `failed`
- [x] `finalizeRuns` - запуск без незавершених завдань або без руху 15 хв закривається
