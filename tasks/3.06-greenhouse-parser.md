# 3.06 Парсер Greenhouse

**Етап 3 — Парсинг і вакансії** · строго TDD

Брати перед 3.04.

Читання вакансій через публічний API Greenhouse. Перший парсер в етапі — на ньому відпрацьовуємо спільний інтерфейс парсера (вхід: URL джерела, вихід: список вакансій або помилка).

Збережена реальна відповідь платформи — у фейковому сервері (картка 3.01).

План: docs/discovery-and-parsing.md розділ 6.

## Рішення (18.11.2026)

- **Спільний формат парсера** (`src/server/parsers/`): вхід - адреса джерела й HTTP-клієнт; вихід - `{ ok: true, vacancies }` або `{ ok: false, error }` з причиною `not-found` (сторінки чи дошки немає, 404), `unreadable` (відповідь не того формату) або `fetch-failed` (збій запиту, з причиною `HttpError`).
- **Вакансія** - лише `externalId`, `title`, `url`, `location` (може бути `null`): рівно те, що показує список Jobs, і ID для ключа. Дату виявлення, ключ і очищення URL парсер не робить - це 3.13 і 3.05.
- **Межі тестування:** `parseGreenhouseJobs(json)` - юніт на справжній відповіді Discord з диска й ручних випадках; `greenhouseBoardToken(sourceUrl)` - форми адрес; `readGreenhouse(sourceUrl, client)` - інтеграційно через фейковий вебсервер.
- **API лише `boards-api.greenhouse.io`.** Документація ([docs.greenhouse.io/job-board.html](https://docs.greenhouse.io/job-board.html)) про регіони мовчить; `boards-api.eu.greenhouse.io` не існує в DNS, `job-boards.eu.greenhouse.io` перенаправляє на `greenhouse.com`. Дошки ЄС не підтримуємо, доки не трапиться справжня.
