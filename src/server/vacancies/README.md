# src/server/vacancies - вакансії

Що сервер робить із вакансіями після того, як парсер їх прочитав: ключ, а з
задачею 3.13 - життєвий цикл (docs/discovery-and-parsing.md, розділ 7).

## Файли

| Файл          | Роль                                             |
| ------------- | ------------------------------------------------ |
| `key.ts`      | `cleanVacancyUrl(url)` - адреса у формі для порівняння |
| `key.test.ts` | Юніт-тести ключа й очищення адреси                |

## Очищена адреса

`cleanVacancyUrl` дає форму, у якій дві адреси однієї вакансії збігаються:

- **без міток відстеження** - `utm_*` і `gh_src` (з плану), `gh_jid` (дублює ID зі
  шляху Greenhouse, знайдено в 3.06), `fbclid` і `gclid` (рекламні мітки Facebook і
  Google). Решта параметрів лишається: `?id=42` розрізняє вакансії;
- **без якоря** (`#apply`) і **без слеша в кінці шляху**;
- **хост у нижньому регістрі**, а регістр шляху - як був: на багатьох сайтах він
  важить;
- **параметри в одному порядку** - `?b=2&a=1` і `?a=1&b=2` однакові.
